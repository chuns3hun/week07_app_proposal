# REVIEW_HANDOFF — 운동 기록 앱 7주차

## 1. 검토 방식
- 사용한 AI: Claude (claude.ai 채팅)
- AI가 한 일: 앱 후보 3개 제시, proposal.md·context-pack.md 초안 작성, 본인 GitHub 3~5주차 저장소를 열어 재사용할 코드 위치 확인
- 검토 기준: ① 과제 요구사항(AC 4개 이상, 정상·잘못된 입력·빈 상태 포함)을 지키는가 ② MVP 기능만으로 약속한 가치를 확인할 수 있는가 ③ 지금까지 배운 범위(setState, ListView, 입력 검증)로 구현 가능한가 ④ 자료표 위치가 실제 파일을 가리키는가
- 확인 방법: 초안을 과제 안내문의 "스스로 확인할 내용" 항목과 하나씩 대조하고, 자료표 링크가 본인 저장소의 실제 파일·커밋을 가리키는지 확인

## 2. AI 제안과 판단

| # | AI 제안 | 판단 | 이유 |
|---|---|---|---|
| 1 | 앱 후보 B(과제 마감 관리), C(오답 노트) | **거절** | 세 후보 모두 규모는 비슷하지만, 운동 기록은 주 3회 이상 직접 겪는 문제라 사용자와 가치를 가장 구체적으로 설명할 수 있음 |

| 4 | AC를 요구치(4개)보다 많은 5개로 작성 | **채택** | AC5(빈 종목명 차단)는 종목 추가 기능의 잘못된 입력 조건이라 필요함. 다음 작업 범위에서는 제외해 부담을 줄임 |

| 6 | 다음 작업에서 종목 추가와 화면 이동 제외 | **채택** | 핵심 가치(직전 기록 확인)를 한 화면에서 먼저 검증하는 것이 우선. 3화면 이동은 그다음 작업 |
