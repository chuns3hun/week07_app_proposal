# 개인 앱 제안서 — 운동 기록 앱

## 1. 문제
헬스장에서 지난번에 어떤 무게로 몇 회를 했는지 기억나지 않는다.
그래서 이번에 무게나 횟수를 얼마나 올려야 할지 정하기 어렵고, 점진적 과부하를 정확히 적용하지 못한다.

## 2. 첫 사용자
- 주 3회 이상 웨이트 트레이닝을 하는 대학생 (본인)
- 현재는 기억이나 휴대폰 메모장에 의존해 기록하고 있음

## 3. 가치
운동 중에 종목을 고르면 **직전 기록(무게·횟수)을 바로 확인**할 수 있어, 이번 세트의 목표를 빠르게 정할 수 있다.

## 4. 핵심 행동
종목 선택 → 무게·횟수 입력 → 저장 → 직전 기록 확인

## 5. MVP 범위

| 구분 | 기능 | 이유 |
|---|---|---|
| 필수 | 종목 추가 | 기록할 대상이 있어야 함 |
| 필수 | 세트 기록 (무게·횟수) | 핵심 행동 |
| 필수 | 종목별 기록 목록과 직전 기록 표시 | 약속한 가치를 확인하는 기능 |
| 보류 | 기록 그래프, 1RM 계산 | 가치에 도움이 되지만 핵심 흐름 완성 후 추가 |
| 보류 | 기록 수정·삭제 | 잘못 입력 시 필요하지만 MVP 흐름 검증에는 필수 아님. 대신 입력 상한(무게 500kg, 횟수 100회)으로 큰 오타를 막음 |
| 제외 | 로그인, 친구 공유, 클라우드 동기화 | 서버가 필요해 이번 범위를 넘음 |

필수 기능 세 개만으로 "직전 기록을 보고 이번 목표를 정한다"는 가치를 확인할 수 있다.

## 6. 제약
- **실행 환경**: Flutter 앱 (Android 에뮬레이터 또는 실기기에서 실행)
- **저장 방식**: 기기 내부 저장 (외부 서버 없음). 구체적인 저장 방법은 **미정** — 수업 진도 확인 후 결정
- **개인정보**: 이름·연락처·계정 등 개인정보를 수집하지 않음. 운동 기록만 기기 안에 저장
- **외부 요청**: 없음 → 네트워크 실패·재시도 조건은 해당 없음

## 7. 화면

| 화면 | 내용 | 이동 |
|---|---|---|
| ① 종목 목록 | 등록한 종목 목록, 종목 추가 버튼 | 종목 선택 → ③ |
| ② 기록 입력 | 직전 기록 표시, 무게·횟수 입력, 저장 버튼 | 저장 → ③ |
| ③ 종목별 기록 목록 | 해당 종목의 기록을 최신순으로 표시, 기록 추가 버튼 | 기록 추가 → ② |

## 8. 데이터

| 항목 | 타입 | 예시 | 규칙 |
|---|---|---|---|
| 종목명 | 문자열 | 벤치프레스 | 비어 있으면 안 됨 |
| 날짜 | 날짜 | 2026-10-26 | 저장 시 자동 입력 |
| 무게(kg) | 숫자 | 60 | 0보다 크고 500 이하 |
| 횟수 | 정수 | 10 | 1 이상 100 이하의 정수 |

## 9. 앱 AC (인수 조건)

| # | 유형 | 행동 | 기대 결과 | 확인 방법 | 상태 |
|---|---|---|---|---|---|
| AC1 | 정상 | 벤치프레스 기록 입력 화면에서 무게 60, 횟수 10을 입력하고 저장 | 기록 목록 맨 위에 오늘 날짜, 60kg, 10회가 표시된다 | 앱에서 직접 입력 후 목록 화면 확인 | 미실행 |
| AC2 | 잘못된 입력 | 무게를 비우거나 음수·문자·500 초과 값을 입력하고 저장 | 저장되지 않고 "무게를 올바르게 입력하세요" 문구가 표시된다 | 빈 값, -5, abc, 600을 각각 입력해 확인 | 미실행 |
| AC3 | 빈 상태 | 기록이 하나도 없는 종목의 기록 목록을 연다 | "아직 기록이 없습니다" 안내가 표시된다 | 새 종목을 추가한 직후 목록 화면 확인 | 미실행 |
| AC4 | 정상(가치) | 기록이 있는 종목의 기록 입력 화면을 연다 | 가장 최근 기록의 무게·횟수가 화면 상단에 표시된다 | 기록 2개 저장 후 입력 화면에서 최신 값이 보이는지 확인 | 미실행 |
| AC5 | 잘못된 입력 | 종목명을 비운 채 종목 추가 | 종목이 추가되지 않고 안내 문구가 표시된다 | 빈 이름으로 추가 시도 | 미실행 |

## 10. 남은 질문
- 저장 방식: 수업에서 다룰 기기 저장 방법(예: shared_preferences, SQLite) 중 무엇을 쓸지 확인 필요
- 저장 방식을 구현하기 전까지는 앱 실행 중에만 기록이 유지됨 (앱 종료 시 사라짐)
